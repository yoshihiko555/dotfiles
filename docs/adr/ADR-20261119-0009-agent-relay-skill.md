# ADR-20261119-0009: 別エージェントへの引き継ぎ・並列依頼は agent-relay スキルが担い、herdr の操作は全 CLI に配る付属スキルに任せる

- ステータス: 採用
- 決定日: 2026-11-19
- 関連: [ADR-20260922-0001](ADR-20260922-0001-herdr-migration-trial.md)（前提。herdr を常用する）

## 背景

herdr のペインで Claude Code・Codex・pi・Antigravity CLI（agy）を使い分けている。
別のエージェントに作業を渡すたびに、ペインの用意、エージェントの起動、それまでの文脈の説明を口頭でやり直している。
例えば、Claude Code で詰めた内容を Codex に渡して Product Design プラグインで画面案を作らせる、といった場面である。
2026-11-18 の `herdr agent list` でも、手作業で起こした引き継ぎ・発注・独立レビュー用のペインが複数並行して動いていた。

herdr には付属スキルがある（`herdr --skill` の出力。herdr 0.9.4 と 0.9.5 で内容は同一）。

- 中身はコマンドの文法と安全ルールに限られ、何を誰にどう渡すかは扱わない
- 説明文は「Herdr が名指しされたときだけ使い、委譲や並列作業に向くというだけでは使わない」としている
- herdr の更新ごとに再生成する運用で（`shared/skills/common/herdr/README.md`）、中身に手を入れると更新のたびに差分を当て直すことになる

この付属スキルは Codex と pi にしか配っていなかった。
Claude Code には「`herdr --skill` でその場で読む」として配っていない（`76135cf` のコミット本文）。
Claude Code の Bash からも herdr を操作できることは確かめてある（2026-11-18、MacBook、herdr 0.9.5。`HERDR_ENV=1` が見え、`herdr agent list` が通った）。
また、「引き継いで」という言い方は、Claude Code に入っている `claude-mem:handoff`（後で再開するための HANDOFF.md を作るスキル）にも当たる。

## 選択肢

### A. 付属スキルに段取りを書き足す（不採用）

- 再生成のたびに書き足した分が消える
- 付属スキルの説明文が委譲を対象外としているので、書き足しても呼ばれる場面がそろわない

### B. 付属スキルを使わず、段取りと herdr コマンドをすべて新しいスキルに持たせる（不採用）

- herdr コマンドの説明が 2 か所に分かれ、herdr を更新するたびに新しいスキル側も追従が要る

### C. 付属スキルは従来どおり Codex・pi だけに配り、Claude Code・agy では必要なときに `herdr --skill` を読む（不採用）

- 説明文が常駐しないので、Claude Code・agy は「herdr で〜して」と頼まれても付属スキルの存在に気づけない
- 段取りのスキルがコマンドの正典として付属スキルを指しても、CLI によって届き方が変わる

### D. 段取りだけを持つ agent-relay スキルを作り、コマンドの正典は付属スキルにして全 CLI に配る（採用）

- 付属スキルは再生成するだけで済み、コマンドの説明は 1 か所にとどまる
- 呼び分けは新しいスキルの説明文だけで決められる

## 決定

**別エージェントへの引き継ぎと並列依頼は agent-relay スキルが担い、herdr の操作方法は付属スキルを全 CLI に配って任せる。**

1. 付属スキルは `herdr --skill` の出力のまま置き、手を入れない。共通スキルとして Claude Code・Codex・agy・pi のすべてに配る
2. agent-relay が持つのは「何を・誰に・どう渡すか」に限る。中身は引き継ぎ資料（以下ブリーフ）の作成、渡す先と起動方法の選択、起動と送信、結果の受け取り方である。
   herdr コマンドの細部と安全ルールは付属スキルを正とする
3. 呼び分けは agent-relay の説明文で行う
   - herdr が名指しされていても、引き継ぎ・委譲の依頼なら agent-relay
   - ペインの操作だけなら付属スキル
   - 受け手を名指ししない引き継ぎメモの作成だけなら handoff 系のスキル
4. 引き継ぎは、相手が作業を始めたのを確かめて終える。並列依頼は、全員の完了を待って結果を集める
5. 文脈はブリーフのファイルで渡し、エージェントに送る指示は 1 行にとどめる。
   ブリーフは受け手が必ず読み書きできる場所に置き、git の対象から外す
6. 決まった組み合わせ（Codex と Product Design など）は名前で呼べるようにする。持ち方は実装に任せる
7. 付属スキルの既定と異なる振る舞いは、agent-relay 側に例外として理由とともに明記する

## 検証

- 2026-11-18〜19、MacBook（herdr 0.9.5、Codex 0.170.0）で、会話を見ていない別のエージェント（Claude Code のサブエージェント）に agent-relay の手順書だけを渡して試した。
  内容は引き継ぎ 1 回（Codex 1 つ）と並列依頼 1 回（Codex 2 つ）で、3 つとも作業を終え、並列依頼の結果はファイルで回収できた
- 同じエージェントに 3 つのスキルの説明文だけを見せ、4 つの依頼文でどれを選ぶかを答えさせた。
  依頼文は「herdrでCodexに引き継いで」「herdrでペイン分割して」「引き継ぎメモを作って」「Codexに引き継いで」で、4 つとも「決定」3 の呼び分けどおりになった
- 未確認の経路が残っている
  - Codex・pi から送る場合
  - 会社用のラッパー（`ccw` / `cxw`）や pi・agy での起動
  - Codex と Product Design の組み合わせを最後まで通すこと

## 影響

- Claude Code と agy にも付属スキルが入り、「herdr で〜して」がどの CLI でも同じスキルに届く。そのぶん、説明文がコンテキストに常駐する
- 会社用 Codex も共通スキルを配る仕組みに乗っているので、付属スキルが入る
- herdr を更新したときは、従来どおり付属スキルを再生成するだけでよい。
  ただし付属スキルの規則が変わったら、agent-relay に書いた例外（「決定」7）を見直す
- 組み合わせ表は、この dotfiles が定義する起動コマンド（`ccw` / `cxw` など）に依存する

## 決定しないこと

- 別マシン（Mac mini（hermes）など）への依頼: herdr にリモートのマシンを登録した時点で、agent-relay に含めるかを決める
- OpenCode と Hermes Agent 自身への配布: どちらも `task sync-skills` の配布先に入っていない。使い始めるときに配布先へ加えるかを決める
