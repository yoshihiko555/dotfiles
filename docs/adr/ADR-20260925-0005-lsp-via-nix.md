# ADR-20260925-0005: LSP サーバーを mason から Nix に移す

- ステータス: 採用
- 決定日: 2026-09-25
- 関連: [ADR-20260924-0004](ADR-20260924-0004-formatters-linters-via-nix.md)（フォーマッタ・リンタの基準版を Nix に集約）、
  [config/nix ADR-20260729-0002](../../config/nix/docs/adr/ADR-20260729-0002-multi-host-adoption.md)（言語ランタイム = mise、それ以外の CLI = Nix）

## 背景

Neovim の LSP サーバー（gopls / pyright / ts_ls / lua_ls）は mason.nvim が入れていた。
一方で gopls / pyright / typescript-language-server / typescript は brew からの移行で Nix にも入っており、二重管理になっていた。

| 問題 | 内容 |
|---|---|
| 版が固定されない | mason は導入時点の最新を入れ、lockfile が無い。2026-07-13 に ts_ls と一緒に `typescript@7`（`tsserver.js` を持たない Go 移植版）が入り、typescript の無いディレクトリで ts_ls が起動しなくなっていた |
| Neovim からしか見えない | mason の bin は Neovim の中でだけ PATH に入る。Claude Code の LSP プラグイン（会社用で typescript-lsp を有効化）は PATH 上のサーバーを使うため、Nix 側が必要だった |
| 境界ルールから外れる | LSP サーバーは言語ランタイムではない CLI なので、境界ルールでは Nix の担当 |

## 選択肢

### A. mason に一本化する

- `:MasonInstall` で手軽に試せる
- 版が固定されず、別環境で同じ版を再現できない。Claude Code の LSP プラグインからは見えない

### B. Nix に一本化する（採用）

- 版は flake.lock で固定され、switch で全ホストに同じ版が入る。Neovim と Claude Code が同じサーバーを使う
- 新しい言語を試すときも `packages.nix` に足して switch する必要がある

## 決定

**B を採用する。**

1. LSP サーバーは共通層 `config/nix/home/packages.nix` に置く（hermes の Neovim でも使うため）。
   対象は gopls / lua-language-server / nixd / pyright / typescript-language-server
2. mason.nvim / mason-lspconfig.nvim は外し、Neovim は `vim.lsp.enable` で起動する。nvim-lspconfig はサーバー定義の提供元として残す
3. typescript は単体で宣言しない。nixpkgs の typescript-language-server は、プロジェクトに typescript が無いときに
   nixpkgs の typescript を使うよう組まれている（プロジェクトの typescript があればそちらを優先）。
   素の `tsc` が要る場面はプロジェクト内の `npx tsc` で足り、言語ランタイム寄りのものを Nix に置く理由が無い
4. Nix の LSP には nixd を使い、nix-darwin / home-manager のオプション補完を有効にする。
   flake の場所は Neovim 設定の実体（リポジトリ内の `config/nvim`）から辿るため、ホストごとの設定は要らない

## 影響

- 移行後、MBP と hermes の `~/.local/share/nvim/mason` は不要になる（switch 後に削除する）
- `lazy-lock.json` から mason 系の 2 件が外れるのは、次に `:Lazy` で同期したとき
- nixd のオプション補完は macOS では `darwinConfigurations.macbook`、それ以外では `homeConfigurations.wsl` の定義を使う。
  hermes 固有のオプションは補完に出ない
