# agent-relay

会話で積み上げた文脈を**ブリーフ**（受け手が読む唯一の資料）にまとめ、herdr のペインに
起動した別のエージェントへ渡す。herdr コマンドの文法と安全ルールの正典は herdr スキル
（無ければ `herdr --skill` の出力）で、本スキルはその上の段取りを決める。

## 2 つのモード

| | 引き継ぎ | 並列依頼 |
| --- | --- | --- |
| 依頼の形 | 「〜に引き継いで」「〜で続けて」 | 「並列で」「〜と〜にレビューさせて」 |
| 受け手 | 1 つ | 1 つ以上 |
| 終わり方 | 相手が作業を始めたのを確かめて終える。結果は待たない | 全員の完了を待ち、結果をまとめて報告する |
| 送り手のその後 | その作業から手を引く | 結果を受けて会話を続ける |

モードが読み取れないときは、受け手が 1 つなら引き継ぎとして扱う。

## 組み合わせ表

ユーザーが名前（または相当する言い方）で呼ぶ定型。表にない起動コマンド（`ccx` など）を
指定されたら、そのコマンドを `pane run` で起動し、kind は中で動くエージェント
（`ccx` なら `claude`）として扱う。

| 名前 | 起動 | kind | 送る指示に足す一文 |
| --- | --- | --- | --- |
| `claude` | `agent start --kind claude` | claude | — |
| `codex` | `agent start --kind codex` | codex | — |
| `pi` | `agent start --kind pi` | pi | — |
| `agy` | `agent start --kind agy` | agy | — |
| `claude-work` | `pane run "ccw"` | claude | — |
| `codex-work` | `pane run "cxw"` | codex | — |
| `design` | `agent start --kind codex` | codex | `@Product Design を使って進めてください（入口は product-design:index）。` |

`agent start` は zsh にコマンドを打ち込むので、シェル関数（`codex()` など）を通る。

## 手順

### 1. 前提を確かめる

`test "${HERDR_ENV:-}" = 1` が通らなければ、herdr の外にいると伝えて止める。
別マシン（Mac mini など）への依頼は扱わない。herdr スキルの `--machine` を案内する。

### 2. 受け手を決める

受け手ごとに、組み合わせ表の名前と**エージェント名**を決める。エージェント名は
`<組み合わせ名>-<話題の英小文字 1〜2 語>`（例: `codex-review`）とし、
`herdr agent list` で生きている名前と重ならないものにする（`[a-z][a-z0-9_-]{0,31}`）。
**起動ディレクトリ**（受け手が動く場所）は送り手の `$PWD`。ユーザーが別の場所を指定したらそれに従う。
以降の `<起動ディレクトリ>` はここで決めた絶対パスを指す。

### 3. ブリーフを書く

受け手ごとに `<起動ディレクトリ>/.agent-relay/<YYYYMMDD-HHMMSS>-<エージェント名>.md` を作る。
受け手は自分の起動ディレクトリなら必ず読み書きできるので、そこに置く。
ディレクトリが無ければ作り、中に `*` だけを書いた `.gitignore` を置く。

受け手は**会話を一切見ていない**。会話の中でしか通じない言い回し（「さっきの案」「例の件」）は、
指している中身に書き換える。見出しは次の順に置く。

```markdown
# <依頼の題>

- 依頼元: <エージェント種別> / <HERDR_PANE_ID> / <日時>
- モード: 引き継ぎ | 並列依頼
- `.agent-relay/` は受け渡し用の置き場で、作業の対象には含めない。

## ゴール
## 決まっていること（理由つき）
## 却下した案（理由つき）
## まだ決まっていないこと
## 関係するファイル・コマンド・URL
## やったこと・うまくいかなかったこと
## 完了条件
## 返し方
```

`## 返し方` は、引き継ぎなら「ユーザーと直接やりとりして進める」と書く。並列依頼なら
「結果を `<起動ディレクトリ>/.agent-relay/<YYYYMMDD-HHMMSS>-<エージェント名>.result.md`
（ブリーフの `.md` を `.result.md` に替えた名前）に書き、最後の返信はそのパスだけにする」と、
絶対パスで書く。
herdr スキルはファイル出力を最初の依頼に入れないとしているが、並列依頼では結果を
画面から読み取らずに確実に集めるため、最初から指定する（本スキルでの例外）。
該当する中身が無い見出しは「なし」と書いて残す。

完了条件: ブリーフだけを読んだ人が、送り手に質問せずに最初の一手を打てる。

### 4. ペインを用意する

分割の向きは、分割するペインの幅（列数）が高さ（行数）の 2 倍以上なら `right`、それ未満なら `down`。
寸法は `herdr pane layout --pane <ペインID>` の `rect` で見る。

- 受け手が 1 つ: 送り手のペインを分割する。
  `herdr pane split --current --direction <向き> --cwd <起動ディレクトリ> --no-focus`
- 受け手が 2 つ以上: 新しいタブを 1 つ作り、そこに並べる。
  `herdr tab create --workspace "$HERDR_WORKSPACE_ID" --cwd <起動ディレクトリ> --label <話題> --no-focus`
  の `.result.tab.tab_id` を控え、`.result.root_pane.pane_id` を 1 つ目に使う。2 つ目以降は、
  新しいタブの中でいちばん大きいペインを `herdr pane split <そのペインID> --direction <向き> --cwd <起動ディレクトリ> --no-focus`
  で割る（`--current` は送り手のタブを割るので使わない）。
  herdr スキルの「頼まれない限りタブを作らない」に対する、本スキルでの例外。
  今のタブを細かく割らずに済ませるため。

ペイン ID は返ってきた JSON から読む。ユーザーがタブやワークスペースを指定したらそれに従う。

### 5. 起動する

- `agent start` の行: `herdr agent start <エージェント名> --kind <kind> --pane <ペインID>`
- `pane run` の行: `herdr pane run <ペインID> "<コマンド>"` の後、`herdr agent get <ペインID>` が
  成功するまで 1 秒おきに最大 30 秒試し、`herdr agent rename <ペインID> <エージェント名>` で名前を付け、
  `herdr agent wait <エージェント名> --timeout 30000` で入力待ちになるのを待つ。

起動時に `agent_not_ready` や `blocked` が返ったら（フォルダの信頼確認など）、
`herdr agent read <エージェント名> --source recent-unwrapped --lines 40` で画面を読み、
ユーザーに見せて判断を仰ぐ。確認ダイアログには送り手から答えない。

### 6. 送る

送る文は 1 行にする。

```
<ブリーフの絶対パス> を読み、書かれている作業を始めてください。<組み合わせ表の一文>
```

`herdr agent prompt <エージェント名> "<送る文>" --wait --until working --until blocked --timeout 30000`
で、相手が作業を始めたことまで確かめる。`timeout` でも届いていないとは限らないので、
送り直す前に `herdr agent read` で画面を確かめる。

### 7. 終える

**引き継ぎ**: ここで終える。

**並列依頼**: 受け手ごとに `herdr agent wait <エージェント名> --timeout 540000` で完了を待つ。
1 回の待機は 9 分以内とし、コマンド実行ツールに時間制限があればそれより長く取る。
終わっていなければ `herdr agent get` で状態を見て待ち直す。
`blocked` になった受け手は画面を読んでユーザーに判断を仰ぐ。
完了したら `.result.md` を読む。無ければ
`herdr agent read <エージェント名> --source recent --lines 120` で最後の返信を読む。

作ったペインとタブは残す。ユーザーに閉じるよう頼まれたら、受け手が作業中でないことを
`herdr agent get` で確かめてから、引き継ぎは `herdr pane close <ペインID>`、
並列依頼は `herdr tab close <タブID>` で閉じる。

完了条件（両モード共通）: ユーザーへの報告に、受け手ごとの次の項目がそろっている。

- エージェント名・ペイン ID（並列依頼ならタブ ID も）・組み合わせ名
- ブリーフのパス
- 状態（`working` / `blocked` / 完了）
- 並列依頼なら結果の要約と、受け手どうしで食い違った点
