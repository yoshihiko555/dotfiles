# security-audit

ファイルは一切変更しない。レポートのみを出力する。

---

## モード判定

呼び出し時の引数で決める。

- **引数が空、`diff`、またはブランチ名** → **diff モード**
  `git diff` の範囲が**新たに持ち込んだ**問題だけを見る。既存の問題は対象外。
- **引数がパス** → **サブツリーモード**
  そのパス配下の既存コードを棚卸しする。

サブツリーモードでは、まず `git ls-files <path>` で対象を確定し、
**ファイル数と概算行数を報告してから**始める。大きすぎる場合はリスクの高い順
（認証情報を扱う → 外部入力を受ける → 破壊的操作をする）に絞り、
**絞った理由と対象外にした範囲を明記する**。

---

## 重点（スタックに依存しない順序）

1. **認証情報**
   ハードコード、ログ出力、エラーメッセージへの混入、
   追跡対象ファイルへの残留、`.gitignore` の漏れ。
2. **外部入力の扱い**
   ユーザー入力・API レスポンス・ファイル・環境変数が、検証を経ずに
   コマンド / クエリ / パス / テンプレートへ流れていないか。
3. **権限と境界**
   認可チェックの欠落、パストラバーサル、
   意図より広く効く破壊的操作（削除・送信・公開）。
4. **依存の脆弱性**
   判定は**パッケージマネージャの audit コマンドを実行した結果のみ**を根拠にする。
   記憶や推測で CVE を挙げない。実行できなければ「未確認」と記録する。

---

## 指摘のルール（必ず適用）

- 実際に悪用可能だと **80% 以上確信できるものだけ**を指摘する。
- 指摘ごとに「**誰が、どの入り口から、何をして、何が起きるか**」の具体シナリオを書く。
  **書けないなら指摘しない。**
- 信頼境界の外にないものを脆弱性と呼ばない。
  ローカル実行の個人用スクリプトで「ローカルユーザーが悪意を持つ」前提は取らない。

### 指摘しないもの（HARD EXCLUSIONS）

- 理論上の懸念、実際の攻撃経路を示せないもの
- DoS / リソース枯渇
- 一般的なベストプラクティス違反（それ自体では悪用できないもの）
- メモリ安全な言語におけるメモリ安全性
- ドキュメント、コメント、Markdown ファイル
- 開発用スクリプトのみで完結し、外部に露出しない経路

---

## 検証フェーズ（必須）

指摘を出し切ったあと、**別のサブエージェント**に各指摘を渡し、
「**これは誤検出である**」と反証させる。

- 反証できた指摘は本編から落とす。
- 落とした指摘は、反証理由を添えて別セクションに列挙する（除外の透明性のため）。

同一コンテキストで自己検証しても通ってしまうため、必ずコンテキストを分けること。

---

## 出力

```
重要度: 種別: path:line
```

の見出しに続けて、説明 → 悪用シナリオ → 修正案。

- 重要度は **Critical / High / Medium のみ**。Low は出さない。
- 末尾に **Refuted Findings**（反証により除外した指摘とその理由）。
- 末尾に **未確認の領域** を必ず列挙する。実行できなかったコマンド、
  読まなかったファイル、判断を保留した箇所。
  **確認していないことを「問題なし」と報告しない。**

---

## 実行上の注意

- ファイルは一切変更しない。
- Codex CLI から実行する場合は `--sandbox read-only` で起動すること
  （frontmatter の `allowed-tools` は Claude Code 固有のため、
  Codex 側の読み取り専用はサンドボックスで担保する）。
- 自分が書いたコードを同一セッションでレビューすると、生成時の理由付けを
  知っているぶん判定が甘くなる。新しいセッションかサブエージェント経由で実行する。
