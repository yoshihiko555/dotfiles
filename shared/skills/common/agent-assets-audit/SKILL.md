# agent-assets-audit

**スコープ**: 指定されたディレクトリ。未指定ならリポジトリ内の
`.claude/` `.codex/` `.agents/` `.gemini/` を探索して対象を報告する。

**役割分担**: 個々のファイルの品質採点は `config-analyze` が担当する。
本スキルは**ツリー全体の整合性と棚卸し**のみを扱い、
個別ファイルの詳細採点はしない（必要なら config-analyze を案内する）。

変更は行わない。レポートのみ。

---

## Phase 0: 資産の一覧化

`git ls-files` と Glob で以下を列挙し、**件数を先に報告する**。

| 種別 | 探索先 |
| --- | --- |
| Skills | `**/skills/*/SKILL.md` |
| Agents | `**/agents/*.md` |
| Hooks | `**/hooks/*` |
| Commands | `**/commands/*.md` |
| Rules | `**/rules/*.md` |
| Context | `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`（各階層） |
| Settings | `settings.json`, `settings.local.json`, `config.toml` |
| Memory | `MEMORY.md` とトピックファイル（存在する場合） |

**symlink を判別すること。** 別ディレクトリからリンクされている資産は
実体側を正とし、重複としてカウントしない。

---

## Phase 1: 整合性チェック（ここが本体）

### 1. hook の登録漏れ・参照切れ

- **ディスクにあるが設定に未登録**の hook ファイル
- **設定に登録されているがファイルが存在しない**（参照切れ）
- イベント種別の指定が設定ファイルのスキーマと合っているか
- タイムアウト値が明らかに不審なもの（極端に長い / 短い）

### 2. skill / agent の参照整合性

- frontmatter の `name` と**ディレクトリ名の不一致**
- `description` の欠落、または極端に長い / 短いもの
- SKILL.md 内から参照されている `references/` `scripts/` の**実在確認**
- 他の資産から名前で参照されているが**存在しない** skill / agent

### 3. 重複

- 同じ目的の skill が複数ある（description と本文の要旨から判定）
- 複数の hook が同じロジックを持っている
- 同じルールが複数の context ファイル / rules ファイルに重複記載されている
- generated（ビルド出力）と source の区別がついていない配置

### 4. 鮮度

`git log` で各資産の**最終更新日**を取得し、以下を報告する。

- **365日以上更新なし**のもの
- 参照している外部ツール・パス・モデル名が、現在の設定と食い違っているもの
  （設定ファイルの実値と突合する）

> **注意**: 「呼ばれた回数」は取得できない。
> 更新日は「使われていないこと」の証拠ではなく、**確認対象の優先順位**として扱う。
> 「未発火」「dormant」と断定しないこと。

### 5. パーミッション

- allowlist に**過度に広いパターン**（`:*` 等）がないか
- 危険な設定値（承認バイパス等）が有効になっていないか
- 参照先が存在しない、明らかに使われていない allowlist エントリ

### 6. 総量

- skill の `description` の**合計文字数**（常時ロードされるコスト）
- context ファイルの行数合計
- `MEMORY.md` がある場合、行数 / バイト数

---

## Phase 2: 除外（必ず適用）

- **generated ファイル**: ビルドや同期の出力先を source と混同しない
  （`.agents/` が `.claude/` のミラーである等のパターンに注意）
- **意図的に眠っている資産**: 年次・四半期など低頻度で使うもの。
  更新日が古いだけで整理候補にしない
- **外部から同期されている資産**: 別リポジトリが正本の場合、
  こちらで直すべきではない。**正本の所在を報告する**

---

## 出力

種別ごとにセクションを分け、以下を明記する。

1. **サマリ表**: 種別ごとの件数、うち問題ありの件数
2. **要対応**: 参照切れ・登録漏れ・危険なパーミッション（実害があるもの）
3. **整理候補**: 重複、長期未更新。**それぞれ確認方法を添える**
4. **総量の所見**: description 合計・context 行数が肥大していないか

末尾に必ず:

- **正本が別リポジトリにある資産**の一覧（こちらで直さないもの）
- **未確認の領域**: 読まなかったファイル、判定できなかった項目。
  **確認していないことを「問題なし」と報告しない。**

---

## 実行上の注意

- ファイルを一切変更しない。削除提案はしてよいが、実行はしない。
- 使用頻度を推測で語らない。取得できるのは更新日までである。
- 個別ファイルの品質を詳しく見たくなったら、
  そのパスを `config-analyze` に渡すよう案内する。
