# ADR-20260915-011: 画像確認にパスコピーと Alfred を使い、Snacks の画像表示を休止

- **Status**: accepted
- **Date**: 2026-09-15

## Context

WezTerm → tmux → Neovim の構成で、画像ファイルの直接表示と Markdown の画像確認を行いたい。
端末構成を維持したまま、残像や表示位置を気にせず画像を確認できる方法を検討した。

`snacks.nvim` の画像表示を試し、Markdown の手動フロートと画像ファイル表示を導入した。
実画面ではカーソルを離しても画像が残り、PNG を開くと neo-tree 側に画像が重なった。
同構成での残像・位置ずれは [上流の報告](https://github.com/folke/snacks.nvim/issues/2165)にもある。

`:ImageClear` による表示中の画像の一括消去はユーザー環境で有効だった。
同じ消去要求をカーソル移動時にも送ることで Markdown の残像は改善したが、
画像ファイルの位置ずれは残り、日常利用の快適さを満たせなかった。

## Decision

**neo-tree で絶対パスをコピーし、Alfred で画像を確認する。Snacks の画像表示は休止する。**

- tree 内の `Y` で選択したファイル・フォルダの絶対パスを `+` レジスタへコピーする。
- パスは引用符やシェル用エスケープを付けず、クリップボードに残す。
- Alfred に貼り付け、対象ファイルで `Shift` を押して Quick Look を開く。
  操作の根拠は [Alfred の公式ドキュメント](https://www.alfredapp.com/help/features/previews/)。
- `lua/plugins/snacks.lua` の `cond = false` でプラグインの読み込みを止める。
  現在の Snacks 設定は画像表示専用なので、キーマップと自動処理もまとめて無効になる。
- 再試用できるよう、設定・消去の回避処理・ロック情報は残す。

## Alternatives

- **Snacks を常時有効にして回避処理を追加する**: 消去は改善したが位置ずれが残る。
  一括消去が同じ端末のほかの画像にも影響するため、常用しない。
- **Neovim から直接 macOS の Quick Look を呼ぶ**: 検討したが未実装。
  今回はパスをクリップボードに残して Alfred に渡す操作を選んだ。
- **tmux 外での利用・端末変更**: 切り分けや将来の再検討候補。
  今回は実機比較を行っておらず、端末構成も変更しない。

## Consequences

- 画像確認はエディタ外になるが、端末内の画像描画に依存しない。
- `Y` は画像以外のファイル・フォルダにも利用できる。
- Markdown の画像リンクから Alfred へ渡す専用操作は今回の対象外。
- 試用で追加した MacBook 用の ImageMagick の Nix 宣言は残す。
  試用時は一時的な Nix 出力を PATH に加えて使い、システム全体の switch は行っていない。
- 無効化の反映には Neovim の再起動が必要。既に残っている画像は終了前に `:ImageClear` で消去する。

### 検証

- ユーザーが `:ImageClear` の消去と、Markdown のカーソル移動時の自動消去を確認した。
- PNG の表示が tree 側に重なることをスクリーンショットで確認した。位置ずれは未解決。
- 画像バッファ離脱・復帰の処理は headless のスタブ検証を実施したが、実画面での完全な正常動作は未確認。
- Lua 構文、無効化設定、`git diff --check` を確認。Nix の変更は `task nix-fmt` を実行済み。
- Alfred の操作は公式仕様に基づく。今回の会話内では実機での成功報告は受けていない。

### 宿題

- Snacks を再試用する場合は `cond` を `true` に戻し、残像・位置ずれ・分割表示・tmux 切り替えを実画面で確認する。
- 再試用の見込みがなくなった時点で、休止中の設定と ImageMagick の必要性を見直す。
