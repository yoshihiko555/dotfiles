# ADR-20260929-014: 言語ごとの DAP アダプター登録を共通化し、Python と TypeScript / Next.js のデバッグを追加する

- **Status**: accepted
- **Date**: 2026-09-29

## Context

[ADR-20260920-012](ADR-20260920-012.md) で共通 DAP 基盤と Go の構成を入れた。同日の追記で、Go 以外のバッファから
launch.json の Go 構成を実行できるように、`dap.lua` に Go 専用の仮アダプターを置いた。

続けて Python と TypeScript（Next.js など）のデバッグを用意する。Java は当面開発しないため見送る。

言語プラグインは FileType で遅延読み込みする一方、launch.json の構成はバッファを問わず一覧に出る。
言語を足すたびに Go と同じ仮アダプターを `dap.lua` に書くと、共通ファイルに言語固有の記述が増える。

## Decision

**`dap.lua` は言語に依存しない登録の仕組みだけを持ち、各言語は `dap-<言語>.lua` から nvim-dap-ui の `opts` に登録を追加する。**

- `opts.adapter_plugins`（type → 言語プラグイン）: 仮アダプターを登録する。最初の実行時にプラグインを読み込み、
  プラグインが登録したアダプター（関数・テーブルのどちらでも）へ渡す。言語プラグインは FileType の遅延読み込みのまま。
- `opts.adapters`（type → アダプター）: プラグインを使わない言語のアダプターを、nvim-dap の読み込み時に登録する。
- 言語を足すときは `dap-<言語>.lua` を 1 つ追加する。lazy.nvim が同じプラグインの `opts` を合成する。
- 読み込みは `on_config` ではなく仮アダプターで行う。`on_config` はアダプター検索より前に呼ばれるが、
  その中で言語プラグインが `on_config` を追加すると、走査中のテーブルへの追加になり Lua では動作が保証されない。
- Go: Delve の存在確認を `on_config` から Go のアダプターへ移す。Go 以外のバッファからの初回実行でも案内が出る。
- Python: nvim-dap-python を `ft = "python"` で読み込み、`setup("debugpy-adapter")` とする。
  debugpy は Nix の `python3Packages.debugpy`（MacBook の `packages.nix`）。type は `python` / `debugpy`。
  実行する Python は nvim-dap-python の解決順（`VIRTUAL_ENV` → `CONDA_PREFIX` → `.venv` / `venv` 等）に任せる。
- TypeScript / JavaScript: 専用プラグインは入れず、Nix の `vscode-js-debug`（`js-debug`）へ直接つなぐ。
  - js-debug はホスト未指定だと `::1` で待ち受けるため、起動引数と接続先の両方に `127.0.0.1` を指定する。
  - `pwa-node` / `pwa-chrome` はそのまま、VSCode の `node` / `chrome` は `pwa-` 付きに読み替える。
  - `node-terminal` は `sh -c <command>` を起動する `pwa-node` に読み替える。単体の js-debug は `node-terminal` を
    起動できず、即座に終了するため。`cwd` は VSCode と同じく、省略時はワークスペース（Neovim の作業ディレクトリ）。
- nvim-dap-python の rockspec により lazy.nvim が nvim-dap を起動時読み込みの spec として追加するため、
  `dap.lua` で nvim-dap に `lazy = true` を明示する。
- キーは追加しない。lockfile は nvim-dap-python の 1 行だけを追加し、既存エントリーは維持する。

## Alternatives

- **type → プラグインの対応表を `dap.lua` に直書きする**: 実装は単純だが、言語の追加で 2 ファイルを触ることになる。
  LazyVim と同じ `opts` 合成で、言語の記述を言語ファイルに閉じる案を選んだ。
- **言語プラグインを nvim-dap と同時に読み込む**: 起動時間には影響しないが、使わない言語まで読み込む。
  言語が増えるほど無駄が大きくなるため採らない。
- **nvim-dap-vscode-js を使う**: 更新が止まっており、js-debug の DAP サーバーへの直接接続で足りるため採らない。
- **`python3.withPackages` で debugpy 入りの Python を入れる**: `python3` が PATH に載り、mise の Python と競合する。
  debugpy パッケージの `bin` は `debugpy` / `debugpy-adapter` だけなので、こちらを使う。
- **Mason で debugpy / js-debug を管理する**: ADR-20260920-012 と同じく、Nix との二重管理になるため採らない。
- **Java も同時に用意する**: 当面開発しないため見送る。jdtls（LSP）の整備が先に必要。

## Consequences

- MacBook の Nix に debugpy 20.7 MiB と js-debug 35.3 MiB、debugpy の依存の lldb 28.0 MiB と lua 0.4 MiB が増える。
  PATH に増えるのは `debugpy` / `debugpy-adapter` / `js-debug` だけで、Python / Node 本体は増えない。
- venv の無いプロジェクトでは、debugpy と同じ Nix の Python 3.14 でプログラムが動き、プロジェクトの依存は読めない。
  venv を作るか、launch.json に `python` を指定する。
- nvim-dap-python は作業ディレクトリの `.env` を環境変数として渡す（VSCode の Python 拡張と同じ既定）。
- `node-terminal` のコマンドは対話端末ではなく `sh -c` で動き、出力は DAP REPL に出る。
  VSCode 固有の `serverReadyAction` は無視される。
- `chrome` / `pwa-chrome` は登録のみで未検証。起動するのは Google Chrome で、Dia ではない。
- Python / TypeScript のテスト用のキー（Go の `dt` / `dT` 相当）は追加していない。

### 検証

- headless の Neovim 0.12.5 で次を確認した。Nix switch は未適用のため、検証プロセスだけ Nix store の
  debugpy と js-debug を PATH に追加した。
  - 起動直後は nvim-dap・dap-ui・言語プラグインのいずれも未読込。合成された `opts` に Go / Python の 3 type と
    JS の 5 type が入る。`.go` で dap-go（構成 7 件・`dt`）、`.py` で dap-python（構成 4 件）が読み込まれる。
  - `.env` バッファから Go の launch 構成を初回実行すると、dlv が無い場合は日本語の案内を出して中止する。
    remote attach は dlv が無くても host / port へ直接つなぐ。
  - `.env` バッファから `debugpy` の launch で実停止。`.venv` の Python で動き、`.env` の値が渡る。
    venv が無い場合は Nix の Python 3.14 で動くことも確認した。
  - `pwa-node` で `.js`、`node`（読み替え）で `.ts`（mise の Node 25 の型除去）が実停止。
    `node --inspect` で起動したプロセスへの `pwa-node` の attach、`node-terminal` の `node app.js` も実停止した。
  - Next.js 16.2.11（Turbopack）の最小アプリで、公式 launch.json の server-side 構成
    （`node-terminal`・`npm run dev -- --inspect`）を `.env` バッファから実行。`app/api/hello/route.ts` の
    ブレークポイントで実停止し、続行後にレスポンスが返った。
- `stylua --check`、`task nix-fmt` / `task nix-check`、MacBook の system build は成功。sudo が必要なため switch は未適用。

### 宿題

- Nix switch 後、新しいシェルと Neovim で `debugpy-adapter` / `js-debug` が PATH から見つかることを確認する。
- 実端末で Python / TypeScript の UI・REPL を確認する。Next.js の client-side（chrome）と full stack 構成は未検証。
- Java が必要になったら jdtls の整備と合わせて追加する。
