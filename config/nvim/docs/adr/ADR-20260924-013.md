# ADR-20260924-013: バッファとタブの一覧を lualine の tabline で表示し、タブを作業画面として扱う

- **Status**: accepted
- **Date**: 2026-09-24

## Context

バッファ機能を使いこなせておらず、「開いているバッファが見えない」「切り替えの打鍵が多い」
「目的のバッファへ直接飛べない」が不満だった。Neovim のタブも使ってみたい。

これまでのバッファ操作は `<leader>bn` / `bp` / `bd` と `<leader>fb`（fzf-lua）だけで、上部の一覧表示はなかった。
タブ操作は `<leader>T` に置いていた。`<leader>t` を gitsigns の表示切替 2 件が使っていたためで、
[ADR-20260313-009](ADR-20260313-009.md) でもこの配置を「今後の拡張に注意」としていた。表示切替はほとんど使っていない。

試用中、タブの表示名が「そのタブでフォーカスしているファイル名」になり、バッファ一覧と同じ名前が左右に並んだ。
色と区切りも同じで、タブとバッファの役割が曖昧に見えた。上には herdr のタブもあり、切り替えの層が 3 段ある。

## Decision

**上部の 1 行に lualine の tabline でバッファとタブを並べ、タブは番号と名前だけの「作業画面」として表示する。**

- 役割を次のように分ける。ファイルの移動は常にバッファで行う。
  - herdr のタブ: ツール単位（nvim / claude / lazygit）
  - Neovim のタブ: 分割レイアウトを崩さずに、差分レビューやデバッグなどの別画面を一時的に開くとき
  - バッファ: ファイル
- `plugins/lualine.lua` の `tabline` で、左に buffers（番号＋名前）、右に tabs を置く。tabs はタブが 2 つ以上のときだけ出す。
- タブにはファイル名を出さず、番号と `t:tabname`（`:LualineRenameTab` と同じ変数）の名前だけを表示する。
  先頭にタブのアイコンを付け、色は tokyonight moon のターミナルモード色（ティール）にしてバッファの青と区別する。
- キーを次のように割り当てる。既存の `<leader>bn` / `bp` / `bd` は残す。
  - `Shift+h` / `Shift+l`: 前 / 次のバッファ（Normal モードの `H` / `L` を上書き）
  - `<leader>1`〜`9`: 上部に表示された番号のバッファへ移動（`LualineBuffersJump!`）
  - `<leader>t`: タブ（`tn` / `tl` / `th` / `td` / `to` は `<leader>T` から移動。`tr` でタブの名前を変更）
  - `<leader>u`: 表示切替（gitsigns の `ub` / `uw`。`<leader>t` から移動）

## Alternatives

- **bufferline.nvim を導入する**: 1 文字でバッファを選ぶ pick や診断表示がある。
  プラグインが増えるため、導入済みの lualine で足りる案を選んだ（[ADR-20260302-003](ADR-20260302-003.md) の最小構成を維持）。
- **scope.nvim でタブごとにバッファを分ける**: タブを作業単位で長く使う場合に向く。
  今回のタブは少数を一時的に使う前提なので採らない。
- **Neovim のタブを上部に表示しない**: タブも使ってみたいという要望と合わないため採らない。
- **バッファ切替を標準の `[b` / `]b` だけにする**: `H` / `L` を残せるが打鍵が多い。
  `H` / `L` は使っておらず、縦の移動は `gg` / `G` で行っているため `Shift+h` / `l` を選んだ。
- **タブの色を紫（Visual モード色）にする**: テーマに馴染まないため採らない。

## Consequences

- Normal モードの `H` / `L`（画面の上端・下端への移動）は使えない。Visual モードの `H` / `L` は標準のまま。
  neo-tree 内の `H`（隠しファイル表示）はバッファローカルなので影響しない。
- `Shift+h` / `l` はグローバルな割り当てのため、quickfix や trouble などのウィンドウで押すと通常のバッファに入れ替わる。
  LazyVim と同じ挙動で、対策はしていない。
- バッファは全タブ共通のまま。タブを切り替えても左の一覧は変わらない。
- タブの色は `lualine_a_terminal` / `lualine_b_terminal` を参照するため、カラースキームを変えると追従する。
- ADR-20260313-009 に記載の `<leader>tb` / `tw` は `<leader>ub` / `uw` に置き換わる。
- チートシート（`custom-keybinds.md` / `git-workflow.md` / `vim-basics.md`）・Git 演習・`PLUGINS.md` を新しいキーに合わせた。

### 検証

- headless の Neovim 0.12.5 で次を確認した。
  - 新しいキーがすべて登録され、旧 `<leader>T*` が残っていない。which-key の重複チェックも問題なし
  - `<leader>ub` / `uw` が git 管理下のファイルでバッファローカルに有効
  - tabline のバッファ番号、タブの番号と名前のみの表示、名前の付与と `%` のエスケープ、ハイライト色
  - `LualineBuffersJump` の移動と、存在しない番号での無操作
  - neo-tree 内で `L` を押してもサイドバーのバッファが入れ替わらない
  - `<leader>tr` の名前の設定・キャンセル・解除（入力欄はスタブ）
- headless では tabline を一度描画するまで `LualineBuffersJump` がエラーになった。実画面では起動時に描画される想定。
- 実画面での tabline の表示はユーザーのスクリーンショットで確認した（タブの表示を直す前の状態）。

### 宿題

- 実画面で `<leader>1`〜`9`、ティール色のタブ表示、`<leader>tr` の動作を確認する。
- タブを作業単位で長く使うようになったら、scope.nvim でタブごとにバッファを分ける案を再検討する。
