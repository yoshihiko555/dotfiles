# ADR-20260920-012: 共通 DAP 基盤と Go のデバッグ構成を分離して導入する

- **Status**: accepted
- **Date**: 2026-09-20

## Context

Neovim でブレークポイント・ステップ実行・変数と呼び出し履歴の確認を行いたい。
まず dotfiles に共通基盤を用意し、Go のローカル実行と単体テストから始める。
Learno の Docker 接続はその後に検証するため、接続先やコンテナパスを共通設定へ混ぜない。

CLI は Nix、言語ランタイムは mise が担当する。
今回の利用端末は MacBook Pro で、Delve は未導入だった。

## Decision

**共通操作は nvim-dap / dap-ui、Go のアダプターとテスト構成は nvim-dap-go に任せる。**

- `plugins/dap.lua` に共通キーと UI の初期化・自動開閉を置く。dap-ui の依存として
  nvim-dap と nvim-nio を導入する。手動の UI 切り替えと終了も残す。
- `plugins/dap-go.lua` は Go の FileType で読み込み、依存の共通 UI を初期化してから
  Go 構成を登録する。`dt` / `dT` は Go バッファ限定。独自アダプターを重複定義しない。
- Delve は `config/nix/hosts/macbook/packages.nix` の `delve` で管理する。
  [Nix の配置規約](../../../nix/README.md#パッケージの置き場)に従い、2 台以上で利用するまでは共通化しない。
  Mason / Homebrew / `go install` では追加しない。存在確認はデバッグ開始時だけ行う。
- パッケージ単位のテストは組み込みの `Debug test (go.mod)`、付近・前回のテストは
  nvim-dap-go の API を利用する。付近のテストは verbose にして成功ログも REPL に出す。
- プロジェクト設定は nvim-dap の標準 provider が作業ディレクトリの `.vscode/launch.json` を読む。
  独自ローダーは作らず、接続先・ポート・ソースパス対応はプロジェクト側に置く。
- 追加プラグイン 4 件だけをインストールし、lockfile の既存エントリーは維持する。

## Alternatives

- **Delve を Mason で管理する**: 既存の CLI 管理方針と異なり、Nix と二重管理になるため採らない。
- **独自の Go アダプターと launch.json ローダーを書く**: 上流の既存機能と重複するため採らない。
- **Docker・他言語・テストランナーも同時に導入する**: 接続やランタイムの問題を切り分けにくいため後続に分ける。

## Consequences

- Neovim 共通設定には Learno 固有のパスや接続先を含めない。
- Lua は repo の実体を参照するため Neovim 再起動で反映するが、Delve の恒久利用には Nix switch が必要。
- 通常編集は Delve 不在でも可能。Go 構成で実行すると日本語の案内を出して中止する。
- TypeScript / Next.js・Python、neotest、toggleterm、インライン変数表示、
  ブレークポイント永続化、Neovim 設定の Nix 化は今回の対象外。

### 検証

- Neovim 0.12.5、mise Go 1.26.1、固定 nixpkgs の Delve 1.27.1 を確認。
  Delve の Go 対応範囲は 1.25〜1.27。互換性チェックを無効化していない。
- Lua 構文・通常起動・DAP/UI 読込・Go キーの限定・Delve 未導入時の案内・標準設定読込を検証した。
- 実端末で which-key の日本語案内・UI 手動開閉・起動待ちからの終了と通常編集への復帰を確認した。
  認証後は実停止時の Scopes / Stacks、Normal / Visual の式評価、REPL と UI 自動クローズも確認した。
- `task nix-fmt` / `task nix-check` / MacBook system build は成功。
  現行世代との差分は Delve の追加のみ。sudo 認証が必要なため switch は未適用。
- 初回は debugserver 起動後にタイムアウトしたが、ユーザーによる Developer Tools Access 認証後に解消した。
  同じ設定で実サンプルのブレークポイント停止、変数・スタック取得、ステップイン / オーバー / アウト、
  続行・終了、パッケージ / 付近 / 前回テストの停止と成功・失敗ログを確認した。
  headless の実セッション検証に加え、新規 Neovim の実端末でも実停止・UI・式評価を確認した。
  新規 Neovim で最初の操作が付近のテストの場合も実停止した。
  詳細と再現手順は [デバッグガイド](../cheatsheet/debugging.md) に残す。

### 宿題

- Nix switch 後の新しいシェルと Neovim で Delve の参照先を確認する。
- Learno 側で Docker の Delve 起動、接続先・ソースパス対応、API リクエストでの停止を確認する。
