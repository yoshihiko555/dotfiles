# ui-context

## 目的

ブラウザで「この要素」と指した情報を、ターミナル側の作業に持ち込む。
DevTools でセレクタを目視コピーして貼る手間をなくすのが狙い。

拡張の実体は `~/ghq/github.com/yoshihiko555/browser-extensions/ui-context/`。

## キャプチャの場所

```
~/.local/share/ui-context/captures/
├── 20260922T163000-123.json   要素の文脈
└── 20260922T163000-123.png    要素の切り抜き画像（撮れた場合のみ）
```

グローバルに 1 つだけ。プロジェクトごとには分かれていないので、
**どのプロジェクトのキャプチャかは URL とファイルの中身で判断すること。**

## 手順

### 1. 最新のキャプチャを読む

既定は最新 1 件。ユーザーが「最新 3 件」などと言った場合はその件数にする。

```sh
ls -t ~/.local/share/ui-context/captures/*.json | head -n 1
```

JSON を読み、同じタイムスタンプの `.png` があれば Read ツールで画像も見る。
画像は要素の切り抜き（周囲 8px の余白付き）なので、見た目の崩れを判断できる。

### 2. 中身を確認する

JSON の主なフィールド:

| フィールド | 内容 |
| --- | --- |
| `selector` | CSS セレクタ（`nth-of-type` ベース。id があればそこで打ち切る） |
| `outerHTML` | 要素の HTML（先頭 2048 文字まで） |
| `computedStyle` | display / position / color / font / box 系の要点 |
| `boundingRect` | 位置とサイズ（CSS px） |
| `url` / `title` | 取得元のページ |
| `comment` | ユーザーが拡張のプロンプトで入れた任意コメント |
| `capturedAt` | 取得時刻 |
| `screenshotKind` | `element`（切り抜き成功）/ `viewport`（切り抜き失敗で全画面）/ `null` |
| `screenshotError` | 画像が撮れなかった場合の理由 |

**古いキャプチャを掴んでいないか確認する。** `capturedAt` が今の作業から
大きく離れている場合は、ユーザーに「これで合っているか」を確認すること。

### 3. 対象のソースを特定する

`url`・`outerHTML` のクラス名やテキスト・`selector` を手がかりに、
リポジトリ内の該当コンポーネントを探す。
セレクタはビルド後の DOM に対するものなので、ソース上の構造とは
一致しないことがある。**セレクタをそのままコードに書かない。**

### 4. 修正する

`comment` に指示が入っていればそれを要件として扱う。
空の場合は、キャプチャの内容を要約したうえでユーザーに何をしたいか確認する。

## 注意

- キャプチャは消えない。放っておくと溜まるので、
  ユーザーから依頼があれば古いものの削除を提案してよい（勝手には消さない）。
- サーバが止まっていると新しいキャプチャは増えない。
  最新ファイルが明らかに古い場合は、`~/ghq/github.com/yoshihiko555/browser-extensions/ui-context/server/start.sh`
  の実行をユーザーに案内する。
